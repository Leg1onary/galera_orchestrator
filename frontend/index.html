Playbooks

Node Down
  1. Проверить wsrep_cluster_size на живой ноде
  2. Если size=1 — кластер non-Primary
  3. Исправить сеть / поднять сервис
  4. Нода автоматически сделает IST
  5. Проверить wsrep_local_state_comment = Synced
Full Cluster Crash
  1. Найти ноду с наибольшим seqno в grastate.dat
  2. На ней выполнить galera_new_cluster
  3. Запустить mariadb.service на остальных нодах
  4. Дождаться IST/SST синхронизации
Split-Brain (2 ноды)
  1. Оба узла считают себя Primary
  2. Остановить MariaDB на одной ноде
  3. Проверить данные — выбрать "правильную" ноду
  4. Перезапустить отставшую через Rejoin

                    Действия с нодами
                

                

                    

                        

                            
Rejoin

                            Action
                        

                        
Переподключить ноду к работающему кластеру после кратковременного отказа. Галера запросит IST (инкрементальный перенос транзакций) если лаг небольшой, или SST (полный снапшот) если нода сильно отстала.

                        
systemctl restart mariadb.service

                    

                    

                        

                            
Stop MariaDB

                            Danger
                        

                        
Штатно остановить сервис MariaDB на выбранной ноде. Нода покидает кластер, cluster_size уменьшается на 1. При 2 нодах без арбитра кластер теряет кворум и переходит в non-Primary.

                        
systemctl stop mariadb.service

                        
⚠ При 2 нодах без арбитра остановка любой ноды прерывает запись в кластер.

                    

                    

                        

                            
Start MariaDB

                            Safe
                        

                        
Запустить сервис MariaDB на выбранной ноде. Нода автоматически присоединяется к кластеру через IST или SST в зависимости от отставания по seqno.

                        
systemctl start mariadb.service

                    

                    

                        

                            
Restart MariaDB

                            Warning
                        

                        
Перезапустить сервис MariaDB на ноде. Равносильно Stop + Start. Используется для применения изменений конфигурации my.cnf без перезагрузки ВМ.

                        
systemctl restart mariadb.service

                    

                    

                        

                            
Kill Process

                            Danger
                        

                        
Принудительно завершить процесс mysqld через SIGKILL. Использовать только если штатный Stop завис. Может привести к corruption при незавершённых транзакциях.

                        
kill -9 $(pidof mysqld)

                        
⚠ Только в крайнем случае. Всегда предпочитать systemctl stop.

                    

                    

                        

                            
Bootstrap

                            Warning
                        

                        
Запустить кластер заново с нуля из одной ноды. Применяется только при полном отказе всех нод. Нода с наибольшим seqno в grastate.dat должна быть bootstrap-кандидатом.

                        
galera_new_cluster  # или: mysqld_safe --wsrep-new-cluster

                        
⚠ Запускать строго на одной ноде с наибольшим seqno. Иначе — потеря данных.

                    

                

            


            
            

                

                    
                    Мониторинг и метрики
                

                

                    

                        

                            
Обновить

                            Info
                        

                        
Принудительно обновить все wsrep-метрики со всех нод немедленно, не дожидаясь следующего планового опроса (по умолчанию каждые 5 секунд).

                        
SHOW GLOBAL STATUS LIKE 'wsrep_%';

                    

                    

                        

                            
wsrep_cluster_status

                            Metric
                        

                        
Статус кластера: Primary — нормальная работа, кворум есть. non-Primary — нода потеряла связь с кворумом, запись заблокирована. Disconnected — нода не в кластере.

                        
SHOW STATUS LIKE 'wsrep_cluster_status';

                    

                    

                        

                            
wsrep_local_state_comment

                            Metric
                        

                        
Состояние ноды: Synced — нода синхронизирована. Donor/Desynced — нода отдаёт SST другой ноде. Joiner — нода получает SST. Joined — нода получила SST, применяет IST.

                    

                    

                        

                            
wsrep_flow_control_paused

                            Metric
                        

                        
Доля времени, когда репликация была приостановлена из-за перегрузки медленной ноды (0.0 = норма, >0.1 = проблема). Значение > 0.25 означает серьёзное отставание ноды.

                    

                

            


            
            

                

                    
                    Настройки и конфигурация
                

                

                    

                        

                            
Reload nodes.yaml

                            Action
                        

                        
Перечитать файл nodes.yaml с диска без перезапуска backend-сервиса. Применяет изменения в списке нод немедленно. Используется после ручного редактирования файла или после добавления/удаления ноды через UI.

                        
POST /api/config/reload

                    

                    

                        

                            
Добавить ноду

                            Action
                        

                        
Добавить запись о новой ноде в nodes.yaml. Укажите имя (например gc03), IP-адрес, порт MariaDB и SSH-порт. После добавления нажмите «Reload nodes.yaml» для применения.

                    

                    

                        

                            
Удалить ноду

                            Danger
                        

                        
Удалить запись ноды из nodes.yaml и из списка мониторинга. Физически ноду из кластера Galera не выводит — только убирает из отображения. Для вывода ноды из кластера используйте Stop MariaDB на ней.

                    

                    

                        

                            
Добавить арбитр (garbd)

                            Action
                        

                        
Добавить Galera Arbitrator — лёгкий процесс, который участвует в кворуме без хранения данных. Критически важен для prod-контура с 2 нодами: при падении одной ноды арбитр сохраняет кворум.

                        
garbd --address gcomm://10.0.0.11:4567,10.0.0.12:4567 --group galera_cluster --log /var/log/garbd.log
